# 登录令牌
不加令牌，在没有登录的情况下就可以得到私有文章数据是不合适的。
令牌过程--login后得到令牌给浏览器，在后续的请求中浏览器会带上这个令牌，然后服务器会解密这个令牌是否符合。
## 要求
    1.令牌里需要有基础的用户数据，以减少对数据库的访问；
    2.令牌是不可随意破解的----jwt
## 令牌---一个字符串
    1.头部（签名算法，令牌类型）+ 有效载荷（base64编码，不安全的不可以放私密） + 加密密钥
## 做法
    1.令牌如何给到浏览器，或者说浏览器哪里会给过来，这一般是前端实现，就是浏览器的请求头里会给出令牌；
    2.如何对一些固定的url进行令牌调查，使用拦截器，对一些url可以进行排除。
    3.如果需要令牌的没有给就401返回response

# 得到用户详细数据
识别令牌与得到令牌的数据其实是两方面的事：
    1.识别：拦截器的方式，拦截所有的请求，成功才会给进入到controller处理中；
    2.获取：是通过参数中的请求指定参数名得到token，从而解析token获取其中的数据。
## 当返回大量用户数据时，会出现一些隐私数据字段不可以被返回，使用@JsonIgnore使转为Jason时忽略掉。

    1.使用线程局部变量ThreadLocal，就是利用静态类方法的方式，将变量直接存储在类里。
    2.直接创建一个静态类，然后就可以作为全局的局部变量。
    3.注意结束后要清除。
**所以获取的方式其实是可以从拦截器中继续获取的。

# validation的分组校验
    1.原因：一般不设置分组默认使用了validation的注解都是在任何请求中都适用，但是，例如在文章分类里，在更新时需要指明id才能知道要改的记录，所以notnull，但是添加时不需要用到id，是自增加的；

    1.在pojo类里定义接口，接口名就是分组名；
    2.在括号里使用group属性，在controller里的参数里也要指明接口变量属于什么校验组。
    3.extends Defult可以加入默认组里，就是一开始的默认所有组的Defult。

# redis优化登录
    因为当用户修改密码后再次登录会获得新的令牌，旧的令牌因为时效性还没有过去，因为令牌是否有效的校验方式是通过能不能从token里提取出数据，其实
    就是有没有失效，所以这会导致旧的令牌依旧可以使用，出现严重问题。
## 实现思路
    1.加入redis数据库，进行同步校验，在登录的时候会存储两份，一个去mysql，一个去redis，修改密码后将redis的进行删除；
    2.校验方式：redis里是否有token。因为密码已经修改，redis数据已经删除，此时就无法识别。每次登录都会将最新的token值覆盖以前的。
    3.重新登陆后redis中才有令牌，此时就可以识别成功了。
# 多环境开发下的配置文件处理使用profile

    1.一般来说环境分为：开发dev，测试test，生产pro；
    2.在配置文件使用---分隔符可以分隔开不同环境配置，当然更多使用多个文件的方式，一个文件对应一个环境，还有一个共同文件用于公共属性和激活指定环境。
    3.文件命名规则：application-xx.yml，在同一个文件夹下即可。
## profile又一个做法：分组一个环境下的不同方向的配置文件
    就是将一个配置文件分为多个文件，这样可以保证一个配置文件不会太大，这个小的配置文件也是application-xx.ybl的格式；
    2.然后在公共配置文件通过group属性设置一个组的分组文件，如："test":testDB,testServer...
