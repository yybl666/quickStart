# 登录令牌
不加令牌，在没有登录的情况下就可以得到私有文章数据是不合适的。
令牌过程--login后得到令牌给浏览器，在后续的请求中浏览器会带上这个令牌，然后服务器会解密这个令牌是否符合。
## 要求
    1.令牌里需要有基础的用户数据，以减少对数据库的访问；
    2.令牌是不可随意破解的----jwt
## 令牌---一个字符串
    1.头部（签名算法，令牌类型）+ 有效载荷（base64编码，不安全的不可以放私密） + 加密密钥
## 做法
    1.令牌如何给到浏览器，或者说浏览器哪里会给过来，这一般是前端实现，就是浏览器的请求头里会给出令牌；
    2.如何对一些固定的url进行令牌调查，使用拦截器，对一些url可以进行排除。
    3.如果需要令牌的没有给就401返回response

# 得到用户详细数据
识别令牌与得到令牌的数据其实是两方面的事：
    1.识别：拦截器的方式，拦截所有的请求，成功才会给进入到controller处理中；
    2.获取：是通过参数中的请求指定参数名得到token，从而解析token获取其中的数据。
## 当返回大量用户数据时，会出现一些隐私数据字段不可以被返回，使用@JsonIgnore使转为Jason时忽略掉。
## 优化方法，出现拦截器中已经得到的claims，但是没有利用，反而在每一个需要claims的controller里都需要解析token的问题。
    1.使用线程局部变量ThreadLocal，就是利用静态类方法的方式，将变量直接存储在类里。
    2.直接创建一个静态类，然后就可以作为全局的局部变量。
    3.注意结束后要清除。
**所以获取的方式其实是可以从拦截器中继续获取的。
